## Comment draft for #221

Confirming on v26.5.31 (macOS darwin 25.5.0), and adding scope — the blast radius is wider
than `eval`, and there is a second defect on the client path that this fix will not reach.

**Every exception class produces the identical empty message**, not just
`SecurityError`/`ReferenceError`: SyntaxError (both redeclaration and malformed),
ReferenceError, TypeError, `throw new Error("...")` with a custom message, and a thrown
primitive. A message passed to `new Error()` is discarded too, so this is not only about
browser-generated errors.

**Unrecoverable through every documented flag** — `--json`, `-v` and `--stdin` all give the
same thing, and exit code 1 is correct:

```
vibium eval --json '<throws>'  →  {"ok":false,"error":"failed to evaluate: script exception: "}
```

That trailing space corroborates the diagnosis in this issue: the format string interpolates
a value that is empty, exactly as `string(evalResult.Result)` would be for an exception.

**The data is reachable — it is only lost on the error path.** Same error, caught inside the
expression, returns in full:

```sh
vibium eval "(() => { try { null.foo } catch (e) { return e.constructor.name + ': ' + e.message } })()"
# → TypeError: Cannot read properties of null (reading 'foo')

vibium eval 'null.foo'
# → Error: failed to evaluate: script exception:
```

`try/catch` returning `e.message` works as a stopgap. Page-independent — same on
example.com, testtrack.org and saucedemo.com.

**Both comparable tools return the message**, so this is not a hard problem peers have also
failed to solve:

```
Playwright 1.62   page.evaluate: Error: CUSTOM_MESSAGE_HERE
Selenium 4.46     javascript error: CUSTOM_MESSAGE_HERE
vibium 26.5.31    failed to evaluate: script exception:      ← nothing after the colon
```

**Every caller of `Evaluate` / `CallFunction` inherits the empty message**, so fixing it at
the source covers more than `eval`:

```go
// clicker/internal/agent/handlers.go:819
if _, err := h.client.CallFunction("", annotateScript, …); err != nil {
    return nil, fmt.Errorf("failed to annotate: %w", err)   // wraps the empty message
}
```

That composition is the `failed to annotate: script exception:` string from
[#156](https://github.com/VibiumDev/vibium/issues/156). #156 is closed and fixed —
`--annotate` succeeds on v26.5.31 — so it is a latent sibling rather than a live one, but
it shows the shape. Fixing `bidi/script.go` at both line 90 (`Evaluate`) and line 146
(`CallFunction`) covers every caller at once.

**One thing this fix will not reach.** The client libraries take a different path —
`vibium:page.eval` → `Router.handlePageEval` — which has no `Type == "exception"` check at
all and calls `sendSuccess` with a nil value, so Python, JavaScript and Java all return
`null` and never raise. That is a separate defect and I have written it up separately
rather than pile it on here. Flagging it only so the fix here is not assumed to close it.

**Why this is worth more than its apparent severity.** Nothing is functionally broken, but
with the message stripped every `eval` failure has to be diagnosed by hand. Concretely: I
hit this on a redeclaration error, could not see the cause, and concluded that `vibium eval`
rejected multi-statement scripts. It does not. That wrong conclusion reached a published
article and three files before a `try/catch` probe caught it. A one-line error string
prevents that whole class of mistake.

## Regression test entry

Retained in `SKILL.md` as B34, tracked against #221.

```sh
vibium go https://example.com
vibium eval '(() => { throw new Error("CUSTOM_MESSAGE_HERE") })()'
```

PASS if: output contains `CUSTOM_MESSAGE_HERE`
FAIL if: `Error: failed to evaluate: script exception:` with nothing after the colon
PARTIAL if: the CLI is fixed but `browser_evaluate` still returns the bare message

The client-path behaviour is tested separately under B36.
