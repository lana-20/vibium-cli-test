# screenshot -o — output path silently discarded; CLI inherits the MCP sandbox

**vibium v26.5.31 · macOS darwin 25.5.0 · verified against repo source**
**Filed as:** _not yet filed_
**Affects:** `vibium screenshot` — `pdf`, `storage` and `record stop` are unaffected

## Summary

`vibium screenshot -o <path>` keeps only the **basename** and writes to
`~/Pictures/Vibium/<basename>` regardless of the directory given. `--help` documents the
flag as `-o, --output string   Output file path`.

This is not an oversight. The CLI dispatches to the same daemon handler the MCP server
uses, and that handler deliberately strips the directory as a path-traversal guard. The
guard is correct for MCP — an agent should not write to arbitrary paths — but the CLI is
a user directing their own shell, and there it silently discards intent. The MCP surface
is *also* the only one with a way to configure the destination.

## Root cause

The CLI command forwards to the MCP-facing handler:

```go
// clicker/cmd/clicker/screenshot.go
result, err := daemonCall("browser_screenshot", screenshotArgs)
```

which flattens the path:

```go
// clicker/internal/agent/handlers.go
// Use only the basename to prevent path traversal
safeName := filepath.Base(filename)
fullPath := filepath.Join(h.screenshotDir, safeName)
```

`h.screenshotDir` is fixed at daemon start with no override:

```go
// clicker/cmd/clicker/daemon_cmd.go
screenshotDir := ""
defaultDir, err := paths.GetScreenshotDir()
if err == nil { screenshotDir = defaultDir }
```

```go
// clicker/internal/paths/paths.go
// GetScreenshotDir returns the platform-specific default directory for screenshots.
// macOS: ~/Pictures/Vibium/   Linux: ~/Pictures/Vibium/   Windows: %USERPROFILE%\Pictures\Vibium\
```

**The guard works** — `-o "../../../../tmp/trav.png"` stays in `~/Pictures/Vibium/trav.png`.
Nothing here argues for removing it. The issue is that it is applied to a surface that
does not need it, and that the surface which does need it is the only one that can be
configured.

## The asymmetry

| Surface | Traversal guard | Configurable destination |
|---|---|---|
| MCP (`vibium mcp`) | needed | **yes** — `--screenshot-dir ./shots`, `--screenshot-dir ""` to disable |
| CLI (`vibium screenshot`) | not needed | **no** — `-o` is discarded; `vibium daemon start --screenshot-dir` → `unknown flag` |

The MCP default is documented (`docs/tutorials/getting-started-mcp.md`:
*"Screenshots are saved to `~/Pictures/Vibium/`"*). There is no equivalent CLI
documentation, and `screenshot --help` describes `-o` as an output **path**.

## Repro

```sh
cd /tmp
vibium go https://example.com
vibium screenshot -o /tmp/check.png
ls /tmp/check.png
```

```
Screenshot saved to /Users/<you>/Pictures/Vibium/check.png
ls: /tmp/check.png: No such file or directory
```

Every path form collapses identically:

| `-o` argument | Written to |
|---|---|
| `shot.png` | `~/Pictures/Vibium/shot.png` |
| `./shot.png` | `~/Pictures/Vibium/shot.png` |
| `~/shot.png` | `~/Pictures/Vibium/shot.png` |
| `/abs/path/shot.png` | `~/Pictures/Vibium/shot.png` |
| `sub/shot.png` | `~/Pictures/Vibium/shot.png` — `sub/` dropped, not created |
| `/abs/nonexistent/shot.png` | `~/Pictures/Vibium/shot.png` — no error |
| `../../../../tmp/shot.png` | `~/Pictures/Vibium/shot.png` — guard working as designed |

`--full-page` and `--annotate` behave the same. Default with no `-o` is
`~/Pictures/Vibium/screenshot.png`, consistent with `--help`.

## Sibling commands are unaffected

They do not route through this handler:

| Command | Honours `-o` |
|---|---|
| `vibium screenshot -o` | **no** |
| `vibium pdf -o` | yes |
| `vibium storage -o` | yes |
| `vibium record stop -o` | yes |

Verified in one run against the same absolute target directory.

## Secondary defects in the same path

Found while hardening; all follow from flattening to a single shared directory.

**Silent success.** No warning that the path was discarded, and the machine-readable
output reports plain success at the redirected location:

```sh
vibium screenshot --json -o /some/dir/g.png
# {"ok":true,"result":"Screenshot saved to /Users/<you>/Pictures/Vibium/g.png"}
```

A script that writes and then reads back from the path it supplied fails at the read,
one step from the cause.

**Collisions overwrite silently.** Because only the basename survives, two runs writing
`shot.png` to different directories become the same file:

```
run 1 → ~/Pictures/Vibium/shot.png   49,720 bytes
run 2 → ~/Pictures/Vibium/shot.png   84,845 bytes   (clobbered, no dedupe, no warning)
```

Concurrent CI jobs, or a matrix run sharding by directory, silently destroy each other's
artefacts.

**A trailing-slash directory produces an extensionless file.**
`filepath.Base("/tmp/")` is `"tmp"`:

```sh
vibium screenshot -o /tmp/
# Screenshot saved to ~/Pictures/Vibium/tmp        ← a PNG named "tmp"
```

**The extension is ignored.** Output is always PNG regardless of what is asked for:

```sh
vibium screenshot -o shot.jpg
file ~/Pictures/Vibium/shot.jpg
# PNG image data, 2400 x 2364        ← PNG content, .jpg name
```

## Impact

Any scripted or CI use that collects screenshots into a working directory, an artefact
folder or a per-run temp directory silently gets nothing there, and parallel runs clobber
one another in the single shared directory. Every capture needs a follow-up copy, and the
source filename must be derived by hand.

## Workaround

```sh
out=/my/target/shot.png
vibium screenshot -o "$out" >/dev/null
cp ~/Pictures/Vibium/"$(basename "$out")" "$out"
```

For pixel-exact work, avoid the command entirely — `toDataURL` returns the canvas or page
bitmap at native resolution without touching the filesystem, and is not device-pixel
scaled the way screenshots are.

## Suggested fix

Naively honouring `-o` would reintroduce the traversal risk on MCP, so the fix should be
surface-aware:

1. **Keep the guard for the agent surface.** `browser_screenshot` invoked over MCP should
   continue to confine writes to the configured `screenshotDir`.
2. **Honour the path on the CLI.** The user's own shell is not an untrusted caller.
   Resolve `-o` (expanding `~`, taking relative paths against cwd), create the directory
   or fail loudly, and write there — matching what `pdf`, `storage` and `record stop`
   already do. This likely means passing a trusted/local flag through `daemonCall`, or
   resolving the path CLI-side before dispatch.
3. **Failing that, at minimum warn.** If the directory is going to be discarded, say so on
   stderr and report `ok:false` — or reflect the true destination — rather than reporting
   success at a path the caller did not choose.
4. **Consider `--screenshot-dir` on `vibium daemon start`,** mirroring `vibium mcp`. Not a
   substitute for honouring `-o`, but it would give CLI users the escape hatch MCP users
   already have.

Independently worth addressing: silent overwrite on basename collision, the
trailing-slash case producing an extensionless file, and the ignored extension.

## Scope

Verified on macOS darwin 25.5.0, vibium v26.5.31. **Not macOS-specific** —
`GetScreenshotDir()` applies the same `Pictures/Vibium` convention on Linux and Windows,
so the behaviour should reproduce there, though it has not been run on those platforms.

No existing upstream issue matches (`screenshot`, `output path`, `Pictures` all searched).

```sh
cd /tmp

rm -f /tmp/vibium-b35-check.png ~/Pictures/Vibium/vibium-b35-check.png

ls /tmp/vibium-b35-check.png
```

PASS if: the file exists at `/tmp/vibium-b35-check.png`
FAIL if: absent, and the output reports `~/Pictures/Vibium/vibium-b35-check.png`

Sibling regression guard — these must keep honouring their paths:

```sh
vibium pdf -o /tmp/b35.pdf      && ls /tmp/b35.pdf
vibium storage -o /tmp/b35.json && ls /tmp/b35.json
```

Traversal guard must remain effective on the MCP surface after any fix:

```sh
vibium screenshot -o "../../../../tmp/b35-trav.png"
ls /tmp/b35-trav.png   # must NOT exist
```
