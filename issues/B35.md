# screenshot -o — directory component of the output path is discarded

**vibium v26.5.31 · macOS darwin 25.5.0 · bundled CfT**
**Filed as:** _not yet filed_
**Affects:** `vibium screenshot` only — `pdf`, `storage` and `record stop` are correct

## Summary

`vibium screenshot -o <path>` keeps only the **basename** of the path it is given and
writes to `~/Pictures/Vibium/<basename>` regardless. Relative paths, `./`-prefixed
paths, `~/`-expanded paths, fully absolute paths and paths containing a subdirectory are
all flattened the same way. Nothing warns, and `--json` reports success with the
redirected location.

`--help` documents the flag as `-o, --output string   Output file path (default "screenshot.png")`.

Three sibling commands that take the same flag honour it correctly, so this is an
inconsistency within a single CLI rather than an intentional convention.

## Repro

```sh
cd /tmp
vibium go https://example.com
vibium screenshot -o ~/shot-home.png
ls ~/shot-home.png
```

**Actual**

```
Screenshot saved to /Users/lanabegunova/Pictures/Vibium/shot-home.png
ls: /Users/lanabegunova/shot-home.png: No such file or directory
```

**Expected** — the file at `~/shot-home.png`.

Not a sandbox or permissions artefact: `~` is unambiguously writable, and vibium itself
reports the redirected destination.

## Scope — path forms

Every form collapses to the basename.

| `-o` argument | Written to |
|---|---|
| `shot.png` | `~/Pictures/Vibium/shot.png` |
| `./shot.png` | `~/Pictures/Vibium/shot.png` |
| `~/shot.png` | `~/Pictures/Vibium/shot.png` |
| `/abs/path/shot.png` | `~/Pictures/Vibium/shot.png` |
| `sub/shot.png` | `~/Pictures/Vibium/shot.png` — `sub/` dropped, not created |
| `/abs/nonexistent-dir/shot.png` | `~/Pictures/Vibium/shot.png` — no error |

`--full-page` behaves identically.

## Scope — sibling commands

Same flag, same documented meaning, different behaviour:

| Command | Honours the `-o` path |
|---|---|
| `vibium screenshot -o` | **no** |
| `vibium pdf -o` | yes |
| `vibium storage -o` | yes |
| `vibium record stop -o` | yes |

Verified in one run against the same absolute target directory: `pdf`, `storage` and
`record stop` wrote there; both `screenshot` invocations did not.

## Silent by default

There is no warning on the discarded path, and the machine-readable output reports
plain success:

```sh
vibium screenshot --json -o /some/dir/g-json.png
# {"ok":true,"result":"Screenshot saved to /Users/lanabegunova/Pictures/Vibium/g-json.png"}
```

A script that writes a screenshot and then reads it back from the path it supplied will
fail at the read, not at the write, which puts the error a step away from its cause.

## Impact

Any scripted or CI use that collects screenshots into a working directory, an artefact
folder, or a per-run temp directory silently gets nothing there. Every capture needs a
follow-up `cp` from `~/Pictures/Vibium/`, and concurrent runs collide in that single
shared directory because the basename is all that survives.

There is no config file or environment variable to change the base directory —
`~/.vibium*` and `~/.config/vibium` do not exist, and the root `--help` exposes no
config surface.

## Workaround

Copy after capture, using only the basename to locate the source:

```sh
out=/my/target/shot.png
vibium screenshot -o "$out" >/dev/null
cp ~/Pictures/Vibium/"$(basename "$out")" "$out"
```

## Suggested fix

Honour the path as documented: if `-o` contains any directory component, resolve it
(expanding `~`, making relative paths relative to cwd) and write there, creating the
directory or failing loudly if it cannot. Keep `~/Pictures/Vibium/` as the destination
only when `-o` is a bare filename or is omitted. This matches what `pdf`, `storage` and
`record stop` already do.

## Platform note

`~/Pictures` is a macOS convention. This was verified only on macOS darwin 25.5.0 with
vibium v26.5.31; the fallback directory and possibly the behaviour may differ on Linux
and Windows. Worth confirming before the fix is scoped.

```sh
cd /tmp
vibium go https://example.com
vibium screenshot -o /tmp/vibium-b35-check.png

```

PASS if: the file exists at `/tmp/vibium-b35-check.png`
FAIL if: it is absent and the output reports `~/Pictures/Vibium/vibium-b35-check.png`

Sibling consistency check — `vibium pdf -o /tmp/b35.pdf` and
`vibium storage -o /tmp/b35.json` must continue to write to the given paths.
